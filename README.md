# Учебный АРМ оператора 112

Клиент тренажёра: Tauri 2 + React 19 + Vite. Учебный вызов принимается
автоматически; оператор разговаривает с заявителем голосом и заполняет карточку
происшествия.

## Как это связано с backend

Всё, что происходит в звонке, ведёт backend
([112-hacaton-backend](https://github.com/hacaton-112/112-hacaton-backend)):
сценарий, ход времени, паника заявителя, распознавание речи и синтез ответа.
Клиент показывает события и отправляет команды.

Соединение одно — WebSocket `/api/v1/voice-pipeline/stream`, и держит его Rust,
а не webview. Причины две: заголовок `Authorization` на рукопожатие webview
поставить не умеет, а backend без него закрывает соединение кодом `4401`; и
речь оператора, которую и так захватывает нативная сторона, не должна ходить
через IPC ради того, чтобы вернуться в тот же процесс.

После первой реплики заявителя клиент один раз шлёт `listen.start`, дожидается
`listen.started` и непрерывно передаёт PCM16 16 кГц по 100 мс. Silero VAD в
ASR-сервисе завершает каждую реплику по тишине, а backend отправляет
`listen.transcript`, не закрывая поток микрофона. Для каждой такой реплики
backend делает ход звонка: спрашивает модель, синтезирует голос заявителя и
возвращает его двоичными кадрами. Rust обрабатывает и непрерывно проигрывает PCM
через native audio sink. Стартовые 160 мс и вся очередь воспроизведения находятся
в Rust; через webview аудио не проходит.

Промежуточные расшифровки оператору не показываются: он работает на слух.

Перед передачей в webview голос заявителя проходит в Rust локальный телефонный
DSP настроен по эталонам из `audio/`: основная телефонная полоса примерно
320–1800 Гц, две ступени high-pass и low-pass,
компрессия и мягкое аналогоподобное насыщение без sample-and-hold и грубой
квантизации. Поверх голоса Rust через случайные интервалы добавляет тихие всплески
линейных щелчков и треска. Большинство длится 45–300 мс, примерно каждый пятый —
450–1500 мс. Помехи проходят через отдельный телефонный band-pass, поэтому
широкополосного радиошипения и постоянного фона нет.

## Запуск

```
bun install
bun run tauri dev
```

Нужен запущенный backend на `VITE_API_URL` (по умолчанию `http://127.0.0.1:3000`),
учётная запись оператора и хотя бы один опубликованный сценарий — список приходит
из `GET /api/v1/scenarios`.

## Учебные сценарии

Пользователям с ролью `instructor` или `admin` в боковой панели доступен раздел
«Учебные сценарии» (`/scenarios`): карточки опубликованных сценариев и брифинг
выбранного — кто звонит, порог оценки и обязательные вопросы с отметкой
критичных. Брифинг открывает рабочее место с уже выбранным сценарием или
отправляет сценарий на правку. Выбранная карточка хранится в адресе, поэтому
после публикации правки каталог открывается сразу на новой версии.

Кнопка «Удалить» после подтверждения убирает сценарий из каталога: начать по
нему новую тренировку и открыть его на правку уже нельзя, но проведённые звонки
и их разборы остаются — backend снимает сценарий, а не стирает его версии.

Правка (`/scenarios/:scenarioVersionId/edit`) открывает опубликованную версию в
конструкторе. Код сценария не меняется, а публикация создаёт следующую версию
поверх той, что была открыта: проведённые звонки остаются на своих версиях. Если
за время правки кто-то опубликовал более новую версию, backend отклоняет правку,
и экран предлагает открыть актуальную. Версия, опубликованная по прежним, менее
строгим правилам, открывается со списком расхождений, которые нужно исправить
перед публикацией.

## Конструктор сценариев

Новый сценарий создаётся на странице `/scenarios/new`. Сценарий можно заполнить
вручную либо получить редактируемый
черновик по синтетическому описанию. Модель не получает поля адреса и геометрии:
преподаватель сам отмечает точку происшествия, центр области и радиус на карте,
а при необходимости вручную вводит текстовую подпись. Описание передаётся во
внешний Alice AI, поэтому форма отдельно предупреждает не вводить реальные
имена и телефоны.

AI-помощник не пишет в базу и не публикует сценарий. Перед публикацией клиент и
backend независимо проверяют факты, условия раскрытия, обязательные вопросы,
эталонную карточку, диапазон паники, соответствие голоса персоне и попадание
точной точки внутрь области геолокации. Публикация — отдельное действие
преподавателя, создающее новую неизменяемую версию `1`.

## Рабочее место ДДС

Оператору доступен отдельный раздел «Карточки ДДС» (`/dds`) для второго типа
практического занятия — реагирования на уже заполненную карточку. Слева
показываются поступившие и завершённые карточки, справа — сведения о
происшествии, адрес, заявитель, службы, действия и хронология.

Первичный статус нужно установить за 30 секунд. Таймер строится по серверному
deadline и не меняет состояние самостоятельно. Дальше интерфейс показывает
только разрешённые backend переходы: принятие, начало реагирования, прибытие,
проведение и завершение работ. Комментарий можно сохранить с любым действием, а
для непринятия карточки и отказа он обязателен. После терминального статуса
показываются технический балл, нарушения и полный таймлайн.

Пока модуль групп и назначений разрабатывается отдельно, новую учебную карточку
можно начать из опубликованного сценария без ввода внутренних идентификаторов.
После интеграции выбор сценария будет заменён очередью назначенных попыток;
backend уже возвращает для этого nullable `trainingAttemptId`.

При первом обращении к микрофону macOS спросит разрешение: текст запроса лежит в
`src-tauri/Info.plist`.

Раздел «Голос» в настройках звука устроен как в Discord: микрофон и динамик,
ползунки «Громкость микрофона» и «Громкость динамика» (0–200 %) и кнопка
«Проверка микрофона» с индикатором уровня и самопрослушиванием. Громкость
применяется сразу, в том числе во время звонка. При 100 % речь оператора уже
усилена в три раза, а громкие места мягко сжимаются вместо хрипа.

## Окно карты

Карта происшествия живёт в отдельном окне (`incident-map`) и получает состояние
звонка через `@tauri-store/zustand`, поэтому открытая карта переживает
перезагрузку основного окна.

Пока идёт звонок и карточку можно править, клик по карте на рабочем месте
отмечает место происшествия. Координаты сразу попадают в карточку, а адрес,
который backend определяет по учебной сессии оператора, приходит строкой
«город, улица, дом». Поля остаются редактируемыми; если адрес определить не
удалось, координаты сохраняются, а адрес вводится вручную. Отдельное окно карты
показывает ту же отметку, но отмечать точку в нём нельзя.
