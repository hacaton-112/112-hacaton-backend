# CPU LLM benchmark

Дата замера: 2026-09-20. Хост: AMD Ryzen 5 5600, 6 ядер / 12 потоков, Docker Linux x86_64. Все замеры сделаны в одном потоке запросов, `ctx-size=2048`, `batch-size=512`, deterministic sampling, по 128 новых токенов. В таблице указано среднее трех прогонов; число потоков подобрано отдельно для каждой модели.

## Скорость

| Модель | Формат | Размер файла | Потоки | Prefill, tok/s | Decode по прогонам, tok/s | Decode среднее, tok/s |
| --- | --- | ---: | ---: | ---: | --- | ---: |
| BitNet b1.58 0.7B | I2_S | 257 MiB | 6 | 280.16 | 99.23 / 101.47 / 90.98 | **97.23** |
| Qwen2.5 0.5B Instruct | Q4_K_M | 469 MiB | 6 | 282.75 | 79.00 / 76.68 / 81.61 | **79.09** |
| Qwen2.5 1.5B Instruct | Q4_0 | 1,017 MiB | 6 | 163.46 | 37.84 / 37.55 / 35.78 | **37.06** |
| BitNet-b1.58-2B-4T | I2_S | 1,133 MiB | 8 | 153.66 | 24.29 / 26.05 / 25.17 | **25.17** |

У BitNet 0.7B дополнительно проверены 4/6/8/12 потоков: decode 94.84 / 97.24 / 95.98 / 52.45 tok/s. Оптимум для этого CPU — 6 потоков. У BitNet 2B оптимум — 8 потоков.

## Пригодность для backend

Проверка: русская инструкция диспетчера 112 с запахом газа и требованием вернуть короткий безопасный ответ и приоритет.

| Модель | Результат |
| --- | --- |
| BitNet 0.7B | Самая быстрая, но это base-модель без chat template и instruction tuning. Chat Completions вернул HTTP 400. Для backend непригодна без отдельного fine-tune. |
| Qwen2.5 0.5B Instruct | API и JSON работают, но модель вернула только приоритет без инструкции по безопасности. Скорость высокая, качество недостаточно для самостоятельного ответа. |
| Qwen2.5 1.5B Instruct | Instruction-модель и лучший кандидат на баланс, но текущий строгий JSON smoke test не прошла. Перед production нужен набор приемочных диалогов и ограниченный шаблон ответа. |
| BitNet-b1.58-2B-4T | На этом CPU медленнее прежних ~30 tok/s llama.cpp и в русском smoke test зациклилась. Не выбирать для текущего backend. |

## Вывод

- Абсолютный лидер raw decode: **BitNet 0.7B I2_S — 97.23 tok/s**, но применять в чате нельзя: это базовая модель без instruction/chat слоя.
- Самый быстрый готовый Instruct-вариант: **Qwen2.5 0.5B Q4_K_M — 79.09 tok/s**, но только вместе с жесткими серверными шаблонами и fallback-ответами.
- Лучший практический баланс из списка: **Qwen2.5 1.5B Instruct Q4_0 — 37.06 tok/s**. Он заметно быстрее BitNet 2B, но его необходимо пропустить через реальные приемочные диалоги проекта.
- **BitNet-b1.58-2B-4T не дает ускорения** на Ryzen 5 5600: 25.17 tok/s. Причина — выигрыш BitNet зависит от поддерживаемого специализированного kernel; текущая официальная сборка для x86 использует стабильный I2_S путь, а экспериментальный TL2 в зафиксированном upstream-коммите не собирается с актуальным runtime.

Для текущего backend production-профиль следует оставить на Qwen2.5 1.5B; Qwen2.5 0.5B использовать как быстрый профиль только там, где ответ ограничен серверным сценарием. BitNet 0.7B оставить как benchmark, BitNet 2B — не включать по умолчанию.
