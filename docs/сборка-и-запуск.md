## Подготовка свежего клона

Клон создан командой `git clone --local --branch docs/verified-build-guide C:\Users\Rizo\RustroverProjects\hackaton\112-hacaton-backend C:\Users\Rizo\RustroverProjects\hackaton\112-build-check` за 3,44 с. В нём изначально не было двух GGUF и MBTiles. Источник инструментальной модели указан в [models/README.md](../models/README.md); загрузку с Hugging Face в этом прогоне не проверяли. `caller.gguf` не распространяется открыто — использован ранее полученный файл. Файлы были скопированы в `models/` и `maps/data/` отдельного клона; загрузка карты из внешнего источника также не проверялась.

В корне клона выполнено `Copy-Item .env.example .env` (0,03 с). В `.env` выставлены `LLM_MODELS_DIR=./models`, `TOOLS_LLM_MODEL_FILE=gemma-4-E2B-it-qat-UD-Q4_K_XL.gguf` и случайный `JWT_SECRET` длиной 64 шестнадцатеричных символа. Для Asterisk пришлось задать непустые `ASTERISK_ARI_PASSWORD` и `ASTERISK_SIP_PASSWORD`: без них он бесконечно перезапускался. Для карты значение шаблона `MAP_TILESERVER_PUBLIC_URL=http://127.0.0.1:8080/` заменено на `/maps/`: до замены JSON стиля выдавал ссылки на HTTP-порт 8080, после замены запрос через HTTPS-шлюз выдал ссылки `https://127.0.0.1/maps/...`. Пароли PostgreSQL, MinIO, Grafana и pgAdmin из шаблона в этом изолированном прогоне не менялись; такая настройка **не проверена для развёртывания вне тестовой машины**.

'C:/Program Files/Git/CN=system112.local'`; попытка с `MSYS_NO_PATHCONV=1` и без аргументов — `req: Can't open "/c/Users/.../infra/tls/certs/tls.key" for writing, No such file or directory`. ## Изолированный контур: проверенные границы

Пробная сборка ASR без доступа сборщика к сети командой `docker build --target models --network none --no-cache --progress plain -t system-112-asr-offline:test services/asr` завершилась ошибкой за 31,28 с: `curl: (6) Could not resolve host: github.com`. `docker compose build --network none` в этой версии Compose не поддерживается (`unknown flag: --network`, 0,17 с). Без заранее полученных артефактов повторная сборка ASR офлайн не прошла; офлайн-сборка остальных трёх образов отдельно не проверялась.

Перенос **готового** образа ASR проверен: `docker save --output $env:TEMP\112-asr-buildcheck.tar system-112-asr-cpu:local` занял 3,13 с и создал архив 0,14 ГиБ; `docker image rm system-112-asr-cpu:local` — 0,13 с; `docker load --input $env:TEMP\112-asr-buildcheck.tar` — 15,64 с. Восстановлен тот же ID образа, после чего контейнер ASR был запущен и стал `healthy`. Перенос остальных образов, всего комплекса вместе с томами и полностью автономный запуск в отключённой сети не проверялись. Для такого контура помимо образов нужны два GGUF, MBTiles и данные хранилищ; проверенный здесь результат относится только к одному архиву образа.

## Фактические отказы и предел проверки

| Отказ | Что подтвердилось |
