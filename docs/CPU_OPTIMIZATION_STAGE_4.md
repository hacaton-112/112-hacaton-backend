## Инварианты

- Engine выбирает разрешённые факты, реакцию и голос; совпадение вопроса не открывает скрытый факт.
- Offline-ошибка разбора не должна включать менее строгий keyword fallback.
- Отмена оператором распространяется наружу; превышение внутреннего бюджета ведёт к безопасной реплике.
- Нельзя объявлять все разрешённые факты произнесёнными: IDs должны соответствовать тексту.
- Внешние API/WS и серверная запись разговора остаются совместимыми.

## Проверки и ограничения

Результаты заполняются после каждого шага. Живой CPU-бенчмарк и работа с реальной моделью не заменяются unit-тестами.

### Шаг 1

- Удалена зависимость request factory от глобального `env` и ветвление `NODE_ENV !== test`.
- Standard/local сохраняет пропуск intent-модели, но передаёт типизированный `undefined` движку.
- Разрешённый Engine одиночный факт в fallback включает поиск готового аудио до генерации.
- Panic/refusal не подменяется ответом банка. Offline использует явный разбор вместо keyword bypass.
- Проверка: `bun run test --runInBand scenario-voice-pipeline-request.factory.spec voice-pipeline.service.spec` — 29 passed.

### Шаг 2

- Восстановлены instruction-override guard, неизвестный вопрос → safe fallback, deadline intent и чтения банка.
- Родительская отмена не превращается в fallback, в том числе если Engine перехватил ошибку resolver.
- Решение сохраняется по session/request и повторно используется при записи хода; offline-ошибка → `[]`, standard keyword → типизированный `undefined`.
- Поздний ответ зависшего provider не попадает в повторно используемый кеш.
- В allowlist добавлены точные Compose aliases `local-llm` и `piper-tts`; запрет внешних endpoint сохранён.
- В `.env.example` пояснено, что `LLM_PROVIDER=local` само по себе не включает offline-hybrid. Пользовательский `.env` не менялся.
- Проверка factory/offline-request: 14 passed; общий прогон — после шага 3.

## Напарнику

До завершения шагов 1–3 не менять одновременно маршрутизацию в request factory и local-llm adapter.
Параллельно можно подготовить синтетический корпус: точные вопросы, перефразировки, отрицания,
несколько вопросов, скрытые факты, повтор, неизвестный вопрос, instruction override.
Нужны ожидаемые IDs и ожидаемая реакция Engine, а не только субъективная оценка текста.
