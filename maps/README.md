# Локальная карта

Каталог содержит конфигурацию и ресурсы автономной карты. TileServer GL читает
`data/moscow-oblast.mbtiles` и не обращается к CARTO или другим внешним
картографическим сервисам.

## Что внутри архива

Москва и Московская область в полной детализации до z14, остальная Россия —
фоном до z8, чтобы при отдалении карта не обрывалась на границе области. Файл
весит около 470 МБ и в Git не хранится: если `data/moscow-oblast.mbtiles` нет,
сервис `map-data` скачивает его с Google Drive проекта перед стартом TileServer
(другой адрес — `MAP_TILES_ARCHIVE_URL` в `.env`).

Проверить архив:

```bash
bun run map:check
```

## Как карта попадает к клиенту

В боевом контуре TileServer наружу не публикуется: gateway проксирует его по
пути `/maps/`, и страница по HTTPS берёт стили, шрифты и тайлы с того же
адреса. Поэтому в `.env` сервера стоит `MAP_TILESERVER_PUBLIC_URL=/maps/` —
без него TileServer выдаёт ссылки на свой внутренний адрес, и карта остаётся
пустой.

В разработке карта поднимается отдельно и слушается напрямую:

```bash
docker compose --profile maps up -d tileserver
```

При этом `MAP_TILESERVER_PUBLIC_URL=http://127.0.0.1:8080/`, а клиент берёт
адрес стиля из `VITE_MAP_STYLE_URL`.

## Образ для боевого сервера

На сервер едет не вся Россия (10 ГБ), а Москва с Московской областью: полная
детализация до z14 в границах области и вся страна фоном до z8, чтобы при
отдалении карта не обрывалась. Такой архив весит ~0.5 ГБ и запекается прямо в
образ TileServer вместе со стилями, sprites и glyphs.

На машине с собранным `russia.mbtiles`:

```bash
bun run map:image
```

Команда вырежет регион (`map:extract`, ~10 секунд), проверит его, соберёт образ
`system-112-training-map:moscow-<дата>` и сохранит его в
`var/map-image/system-112-training-map-moscow-<дата>.tar` (~800 МБ).

На сервере:

```bash
docker load -i system-112-training-map-moscow-<дата>.tar
```

и в `.env` сервера:

```bash
MAP_TILESERVER_IMAGE=system-112-training-map:moscow-<дата>
MAP_TILESERVER_CONFIG=/map/config.json
```

После этого `docker compose --profile app up -d` поднимает карту из образа:
ни `maps/data`, ни шрифты, ни интернет на сервере не нужны. Без этих
переменных TileServer по-прежнему читает `maps/` с диска — так работает
разработка с полной Россией.

За пределами области детальных тайлов нет: там карта показывает только фон
до z8, а при приближении остаётся пустой.

## Запуск

Только карта:

```bash
docker compose --profile maps up -d tileserver
```

Весь production-стек вместе с картой:

```bash
docker compose --profile app up -d --build
```

Стили доступны по адресам:

- тёмная тема — `http://127.0.0.1:8080/styles/dark-matter/style.json`;
- светлая тема — `http://127.0.0.1:8080/styles/positron/style.json`.

Оба стиля (CARTO Dark Matter и Positron) читают один и тот же
`russia.mbtiles`, поэтому вторая тема почти не занимает места. Для приложения
на другом компьютере замените `127.0.0.1` адресом backend-сервера.

## Проверка автономности

После первого получения Docker-образов сервер можно отключить от интернета и
проверить локальные ресурсы:

```bash
curl -f http://127.0.0.1:8080/styles/dark-matter/style.json
curl -f http://127.0.0.1:8080/data/openmaptiles.json
curl -f http://127.0.0.1:8080/fonts.json
```

В отданном `style.json` не должно быть ссылок на `cartocdn.com`.

В production задайте `MAP_TILESERVER_ALLOWED_HOSTS` списком разрешённых имён и
IP-адресов через запятую. Если переменная не задана, TileServer разрешает любой
`Host`, что удобно в изолированной локальной сети, но не подходит для публикации
порта 8080 в интернет.
